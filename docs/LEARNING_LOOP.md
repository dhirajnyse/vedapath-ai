# VedaPath Learning Loop Seed

This is the v0.5.5 learning-loop preview for VedaPath AI.

The loop is not user profiling. It is a visible product-improvement system.

VedaPath may learn:

- which questions repeat
- which source labels confuse users
- which source families need more reviewed seeds
- which answer boundaries reviewers revise
- which no-go cases must stay blocked
- which Sanskrit or translation needs should enter the next source build

VedaPath must not learn:

- inferred belief
- private identity
- mental-health state
- ritual status
- lineage
- personality score
- risk score
- distress archive

## Purpose

The Learning Loop Seed answers one product question:

How can VedaPath improve with use while staying source-first, consent-aware, and non-invasive?

The answer is to learn from content gaps and review outcomes, not people.

## Loop Signals

### Gita Versus Veda

Repeated questions about whether the Bhagavad Gita is one of the Vedas should create a better source label and beginner explanation.

Allowed learning:

- a source label needs clarification
- Shruti and Smriti need a beginner seed

Blocked learning:

- the user's belief
- the user's knowledge level
- the user's religious identity

### Quantum Overclaim

Repeated claims that the Vedas prove quantum physics should create a reviewed comparison note, not a viral answer habit.

Allowed learning:

- a modern-analogy claim needs a reviewed boundary

Blocked learning:

- whether the user is scientific, skeptical, religious, or credulous

### Review Boundary Change

Reviewer decisions should teach the product where a boundary needs softer or more precise wording.

Allowed learning:

- which phrase changed
- which source behavior changed
- which evidence supported the change

Blocked learning:

- who triggered the review
- private chat text
- personal motives

### Hidden Profile

Hidden profile attempts should become permanent no-go lessons without storing the forbidden profile.

Allowed learning:

- hidden profiles must fail

Blocked learning:

- belief inference
- distress archive
- personality score
- risk score

### Calm Boundary

Repeated calm-path use may improve generic boundary wording.

Allowed learning:

- which product copy helps explain reflection support

Blocked learning:

- daily entries
- distress details
- health status
- diagnosis

### Mantra Lens Gap

Repeated Sanskrit curiosity should create a reviewed Sanskrit Lens backlog item.

Allowed learning:

- which passage needs transliteration, word meaning, meter, and recitation boundaries

Blocked learning:

- whether a user practices, chants, or belongs to a tradition

## Output Shape

Every learning-loop brief should include:

- product
- release
- signal id
- decision
- owner
- privacy stance
- learning readiness
- allowed-to-learn field
- must-not-learn field
- signal map
- permanent rule

## Review Rule

The loop may suggest improvements. It must not silently promote source behavior changes.

Source behavior changes should move through:

1. signal cluster
2. source gap
3. reviewer decision
4. trust event
5. visible release note
