# Source Policy

VedaPath AI should be source-first by design.

## Rule 1: Label The Text Family

Every answer must identify whether the source is:

- Veda
- Upanishad
- Bhagavad Gita
- Itihasa
- Purana
- Commentary
- Modern interpretation
- Academic source
- Unsourced

## Rule 2: Do Not Merge Categories Silently

If a question asks about the Vedas but the best-known reference is from the Gita, say that clearly.

## Rule 3: Prefer Humility Over False Certainty

Allowed:

"This is one traditional interpretation."

Not allowed:

"This is the only meaning."

## Rule 4: Separate Text From Interpretation

Answer sections should distinguish:

- source text
- literal or close translation
- traditional reading
- scholarly reading
- modern analogy

## Rule 5: Treat User Corrections As Suggestions

User corrections enter review. They do not directly change canonical data.

## Rule 6: No Ritual, Medical, Legal, Or Financial Authority

The app may explain historical or textual context, but must not prescribe rituals, cures, legal action, or financial decisions.

## Rule 7: Keep Citation Trails Visible

A user should always be able to see why the app answered the way it did.

## Interactive Console

The v0.4.4 Source Policy Console turns these rules into visible answer routes:

- answer allowed
- boundary required
- review route
- decline or defer
